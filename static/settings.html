①

生成模型（LLM）

▾

由 LightRAG 调用的生成模型。接入方式、模型名、接口地址与密钥都在这里统一管理。

填写 LightRAG 支持的提供方名称。
OpenAI 兼容服务通常填写 base URL。
②

嵌入模型（Embedding）

▾

负责把文档编码成向量。换模型或维度后需要重建知识库。

③

重排序模型（Rerank）

▾

可选：对检索结果再排序，提升准确度；不用时选“关闭”。

④

向量存储（Vector Store）

▾

当前知识库使用本地文件向量库（无需 Docker / Qdrant）。如需切回 Qdrant，把存储类型改为 Qdrant 后保存并重启；切换向量库类型后通常需要用「切换本地向量库.bat」或重新上传文档来重建索引。

分块与召回

⑤

存储路径

▾

运行数据默认存放在 %LOCALAPPDATA%\ProfileAI。可填写绝对路径；相对路径按用户数据目录解析。

⑥

入库质量校验（Quality Gate）

▾

上传的文件先在本地解析为 Markdown 再做质量校验：只有通过校验的内容才会进入知识库。 这道门没有总开关（Phase 18 起 QUALITY_ENABLED 已失效）：校验恒定运行，没通过的文件只能在 上传卡片上点「仍要入库」由你自己放行，档案里会留下「人工放行」记录。 留空表示沿用 .env / 内置默认值；选择 standard / strict / loose 时，下面的具体阈值由预设决定（自定义数值会被忽略）。

⑦

入库确认（Ingest Confirm）

▾

质量校验通过不等于直接入库：文件会停在「待确认」，由你点「入库」或「跳过」——中间那一步永远由你决定。
always 每个文件都问你（默认，最稳）；auto 让建议说话——「建议直接入库」的自动放行， 提示「再看一眼 / 谨慎入库」的仍会停下问你；off 通过校验就直接入库（不推荐：错内容也会写进知识库）。
留空表示沿用 .env / 内置默认值；改完需重启服务生效。上传卡片上还有「本次运行内全部允许」的临时开关（重启即失效）。

⑧

文件夹轮询（收件箱自动入库）

▾

把文件复制或移动到用户数据目录的 inbox 就会自动入库：程序每 N 秒扫一次， 等文件「长稳」（连续两轮大小不变）后受理，原件移动到 ProfileAI\data\originals\年月\ 留档， 内容完全相同（sha256 一致）的文件不再入库第二次（归档到 inbox\_taken）。
它与网页上传走同一条流水线：解析、质检、留档规则完全一致；不一样的只有 入库确认（本卡片单独设置，默认 auto）。受理不了的文件（类型不支持 / 超过上传上限） 会移进 inbox\_failed 并附一份 .reason.txt，不会删除。
留空表示沿用 .env / 内置默认值（开关 false、间隔 10 秒、确认 always）；改完需重启服务生效。 看进度请打开 文件管理 页。

⑨

OCR 文字识别

▾

用于扫描件、图片，以及 Word / PPT / PDF 里的内嵌图片。默认 OCR_MODE=off：程序不向任何外部服务发送文件，需要识别的文件只会被拦下并提示。
云端 PaddleOCR-VL（paddle）会把文件发送到外部服务；本机 PaddleOCR（local）在本机识别、不出网（需自行安装）。 内嵌图片默认会先把文档停在「需要识别」状态，只有你点「识别图片」才真正外发。

⑩

▾

上传限额、允许的文件类型、日志级别、问答技能路由与回答生成方式（服务端参数，改完需重启生效）。

开启后图片问题返回 [img-n] 图片卡片；保存后需重启生效。默认关闭。
生成模型由上方「生成模型」统一配置。
